# 分诊判据

后台分诊进程会把本文件**原样注入**给模型。改这里就能改分诊行为，不用改代码。

---

## 核心规则

一条事项算 **clear（清楚）**，当且仅当下面两条**同时**成立：

1. **能一句话说出「下一步具体做什么」** —— 不是"去做这个游戏"，而是"先装 Godot、建空项目、放一个方块"这种可以立刻动手的动作。
2. **能判断「做完没做完」** —— 存在一个可观察的判据。

两条都成立 → `clear`
任一条不成立 → `vague`

## 容易误判的情况

- **提到具体仓库/文件但是巨大工程** → 仍然 `vague`。有专有名词 ≠ 有范围。
  （例：「给 sopho-harness 补测试」下一步说不清补哪里、完成判据也不明确 → `vague`）
- **没有专有名词但是单一动作** → `clear`。
  （例：「催房东修水管」→ 下一步：再催一次；判据：对方回复 → `clear`）
- **"想""考虑""研究一下""搞清楚"开头** → 几乎总是 `vague`。这类词本身就是"还没想清楚"的标记。
- **纯提醒类**（等我、等回复、等截止日）→ `clear`。它不需要分解。

## note 怎么写

一句话，说清**缺哪一条**，让用户能立刻判断你判得对不对。

- 好：`缺范围与完成判据`
- 好：`工程规模未定，下一步无法具体化`
- 坏：`太模糊了`（等于没说）
- 坏：`建议先做需求分析`（这是建议不是判断）
