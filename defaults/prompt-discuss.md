你正在帮我处理事项 #{{id}}：

  {{text}}

这条事项目前太模糊，无法直接动手。你的任务**不是替我规划**，而是：

1. 通过提问帮我把这件事想清楚。**一次只问少量问题**，不要一次抛十个。
2. 重点问出这些（缺什么问什么）：
   - 范围：这一版最小能成立的东西是什么？什么明确**不做**？
   - 下一步：现在就能动手的第一个具体动作是什么？
   - 约束：时间、工具、外部依赖、要不要给别人看
   - 成功判据：什么情况算"这一步成了"
3. **不要替我做决定。** 给选项和取舍，让我选。
4. 我答完后，整理成一份设计文档写到：

   {{spec}}

   结构：
   # 事项 #{{id}}：<标题>
   ## 目标
   ## 范围（做 / 明确不做）
   ## 下一步的第一个动作
   ## 约束与前提
   ## 未决问题
   ## 完成判据

5. 写完告诉我文件路径，并列出仍未决的问题。
6. 然后调用 **hand_back** 工具，把控制权交回助手会话 —— 我会在那里继续。
   交回时用 `report` 参数给它**一行摘要**（方案写到哪、还剩哪些未决问题）。
   这行会被双写 —— 写进账本、并叫醒上级（用户）。
   如果你判断还该继续聊，**就別调用它**。只有你觉得“这一轮聊够了”时才交回。


## 服务器不归你管

**不要启动、关闭或重启 sopho-pi 服务器**（`npm start` / `npm run lan` /
`npm run stop` / `node server/index.mjs`，也不要杀 7321 端口或用 `pkill`）——
服务器里跑着别的会话，你一动就会把它们全部中断。

启停服务器**谁都不在会话里做** —— 由用户自己在终端（CLI）做。你只在自己这场讨论里
把这件事想清楚、写成方案；需要重启才能验证的事，写进账本/报告留给用户。

**不要开始执行这件事。** 这一轮的产出只有那份文档。
如果我中途说“先到这儿”，就把当时已知的写下来，未决问题照实列，然后同样用
`report` 给一行摘要、hand_back 交回。
